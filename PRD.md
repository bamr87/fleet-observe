# Product Requirements Document (PRD): fleet-observe

> Observability stack for the bamr87 fleet: OpenTelemetry Collector, Prometheus and Grafana, wired for every fleet service.

Open work is tracked in [GitHub Issues](https://github.com/bamr87/fleet-observe/issues) and as `status: planned` entries in [features/features.yml](features/features.yml).

## 1. Overview

Metrics, traces and dashboards for the whole fleet from one compose file, ready to move onto the fleet-infra cluster.

| Version | Date | Notes |
| --- | --- | --- |
| 0.1 | 2026-10-28 | Initial requirements and phased roadmap (repo foundation). |

## 2. Goals

- Run OTel Collector + Prometheus + Grafana locally with one command
- Instrument fleet services with OTLP
- Ship dashboards and alerts as code

Non-goals (near term): production hosting, paid services, anything outside the roadmap below without a PRD change.

## 3. Users

- The maintainer, learning opentelemetry (collector pipelines, otlp), promql and alerting rules by building.
- Fleet agents (hub evolution loop, backlog fan-out, `evolve` lane) that grow the repo one reviewed PR at a time.
- Fleet tie-in: Collects telemetry from ragio-ai, fredgar-ai, law-ai and the hub's fleet activity log; complements the hub's ELK kit.

## 4. Requirements

Phases are the build order: an agent picks the earliest unserved requirement first.

### 4.1 Phase 1 — Foundation

- FR1: docker compose stack (otel-collector, prometheus, grafana) validates and starts
- FR2: Prometheus scrapes the collector's own metrics

### 4.2 Phase 2 — Core

- FR3: Grafana datasource and a fleet overview dashboard provisioned from files
- FR4: OTLP instrumentation guide and example for a fleet service

### 4.3 Phase 3 — Fleet integration

- FR5: Alerting rules for service availability
- FR6: Helm deployment onto fleet-infra

### 4.4 Non-functional

- NFR1: CI (`.github/workflows/ci.yml`, the fleet standard gate) passes on every PR.
- NFR2: No secrets or credentials are committed; configuration comes from environment variables.
- NFR3: Autonomous lanes are off by default, open pull requests only, and never merge.
